## 0.3.3 — 26.11.2026

- Добавлен эндпоинт **`/include_content`** (и `/include_script`) — по нему WebCTRL
  встраивает аддон в свой интерфейс. Без него при открытии через «средство
  отображения аддонов» была ошибка `The requested resource [/twpi/include_content]
  is not available`.
- `/include_content` отдаёт iframe с обычной страницей аддона: наш тёмный CSS и
  идентификаторы элементов не задевают страницу WebCTRL, а переходы внутри аддона
  остаются в этом же iframe. У `index.html` появился режим `?embed=1` — прячет
  собственную шапку и подвал.

## 0.3.2 — 26.11.2026

## 0.2.5 — 26.11.2026

**Найдена настоящая причина исчезновения аддона после перезапуска.**

WebCTRL считает файл веб-аддоном, только если в архиве есть явная запись-каталог
`webapp/`. В `ExtensionManager.supportsType` (декомпилировано из WebCTRL 8.0):

```java
ZippedFile zippedFile = new ZippedFile(fileOrDir);
bl = zippedFile.getEntry(type + "/") != null;   // type = "webapp"
```

`build.ps1` создавал только файловые записи (`webapp/index.html`, …), записи
`webapp/` не было — при старте сканирование папки `addons` такой файл пропускало.
Отсюда и симптом: вручную ставится, в списке появляется, после перезапуска
исчезает, хотя файл лежит в папке аддонов.

Теперь упаковщик добавляет directory-записи для всех каталогов. Проверка:
в архиве есть `webapp/` и `webapp/WEB-INF/`.

## 0.2.4 — 26.11.2026

- `info.xml` возвращён к простому виду, как у рабочих аддонов: без XML-декларации
  и без ссылок `&#…;`, описание на латинице. После правки 0.2.2 аддон перестал
  переживать перезапуск WebCTRL — это единственное отличие от weather/termoheatmap,
  которые работают.
- Сборка снова без подписи: у рабочих аддонов подписи нет, лишняя переменная
  в опыте не нужна. Возможность подписи осталась (`-Sign`).

## 0.2.3 — 26.11.2026

- **Аддон подписывается** (`META-INF/ADDON.SF` + `ADDON.RSA`) — без подписи
  WebCTRL убирает аддон из списка после перезапуска.
- В `build.ps1` добавлен шаг подписи: `-Sign -Keystore <addoncert.keystore>`,
  пароль из `-Storepass` или переменной `ADDON_KEYSTORE_PASS`.

## 0.2.2 — 26.11.2026

- Описание в `info.xml` переведено в XML-ссылки на символы (`&#1048;…`), файл стал
  чистым ASCII. Раньше WebCTRL читал его не как UTF-8 и на странице «Сведения»
  показывал «Р РµР·…». Теперь кодировка парсера не важна.

## 0.2.1 — 26.11.2026

- Заголовок диаграммы следует за шагом: «История по дням / по неделям / по месяцам».
- Диаграмма получила шкалу слева (0…максимум с округлённым шагом) и подписи
  значений над столбиками — раньше при 30 днях цифр не было вовсе.

## 0.2.0 — 26.11.2026

Первая полноценная версия: от разового расчёта до списка помещений с историей.

**Добавлено**

- Список помещений с именами: `rooms.jsp`, хранение в `<catalina.base>/conf/twpi-rooms.json`.
- Несколько датчиков на помещение; внутри помещения T и RH усредняются по часам,
  поэтому комната с четырьмя точками не «перевешивает» комнату с одной.
- Быстрое заполнение: вставка списка адресов с автоматической группировкой по папкам.
- Карточки помещений на главной: TWPI, покрытие, T/RH, цветовая оценка.
- Страница помещения: большой TWPI, шкала, диапазоны T/RH, таблица датчиков,
  диаграмма с адаптивным шагом (день / неделя / месяц).
- Кэш часовых рядов: 400 суток, TTL 10 минут, общий для списка, карточки и истории;
  подпись «данные из кэша, N мин назад» и принудительное обновление.
- Поиск точек по GEO-дереву (`tree.jsp`) с готовыми кнопками «в T» / «в RH».
- Страница диагностики контекста (`status.jsp`): версия аддона, Java, Tomcat,
  читается ли `web.xml`, загружается ли сервлет.

**Исправлено**

- Классы собирались под Java 11 и не загружались на WebCTRL 6.5 (Java 8) — теперь
  цель Java 8.
- `room.jsp` отдавался без `charset` (Jasper читал файл как ISO-8859-1) — добавлена
  директива `page`.
- Период на карточке считался по всему прочитанному архиву: `computeMulti` не
  фильтровал часы по окну — исправлено.
- Сэмплы с ненулевым `getSpecialValue()` отбрасывались, а в 6.5 такая метка есть
  у всех нормальных измерений — фильтр убран, остался `TrendType.DATA`.
- Lookup ID собирался с двойным `#`; путь теперь накапливается при обходе дерева.
