# TWPI — аддон WebCTRL

Индекс сохранности (Time-Weighted Preservation Index) по трендам температуры и
относительной влажности: список помещений, несколько датчиков на помещение,
карточки с оценкой и история по месяцам.

**Версия 0.3.6** · установочный файл [`dist/twpi.addon`](dist/twpi.addon) · [релизы](https://github.com/maxef22/twpi/releases) · контекст `/twpi`

## Что делает

- **Помещения.** Список с именами; у каждого — один или несколько датчиков, датчик
  это пара трендов (температура + влажность).
- **Главная страница.** Карточки помещений: TWPI, покрытие периода, средние T/RH,
  цветовая полоса (≥60 зелёная, 40–60 жёлтая, <40 красная). Период 7 / 30 / 90 / 365 / 550 дней.
- **Страница помещения.** Большой TWPI, шкала, диапазоны T/RH, таблица датчиков с
  состоянием каждого тренда, диаграмма — по дням (7 и 30 дней), по неделям (90),
  по месяцам (365 и 550) с подсказками по каждому столбику.
- **Разовый расчёт** по двум адресам — для проверки точки без заведения помещения.
- **Поиск точки** по GEO-дереву с кнопками «в T» / «в RH».
- **Диагностика** контекста: версия аддона, Java, Tomcat, читается ли `web.xml`,
  загружается ли сервлет.

## Как считается

PI (IPI, T в K, RH в %):

```
PI = exp((95220 − 134.9·RH) / (8.314·(T+273.15)) + 0.0284·RH − 28.023) / 365   [лет]
```

TWPI — среднее **скоростей** 1/PI, а не самих PI:

```
TWPI = N / Σ(1/PIᵢ)
```

Ряды T и RH приводятся к часовым интервалам. Если в помещении несколько датчиков,
на каждом часе T и RH усредняются по тем датчикам, у которых есть данные, и PI
считается один раз — помещение с четырьмя точками не «перевешивает» помещение
с одной.

Контрольные значения: 20 °C / 45 % → 51 год (точка отсчёта IPI ≈ 50), 20/50 → 44.6,
15/50 → 83.8, 25/50 → 24.3.

## Установка

```powershell
.\build.cmd          # → dist\twpi.addon
```

Файл ставится штатным средством WebCTRL (*Add-ons → Install*). Имя файла задаёт
контекст: `twpi.addon` → `/twpi`.

Открывать страницы нужно **из интерфейса WebCTRL**: сервлеты используют сессию
оператора (`getUserSystemConnection`). При прямом открытии без сессии будет `401`.

## Формат info.xml

Держим файл в том же простом виде, что у рабочих аддонов (weather, termoheatmap):
без XML-декларации и без ссылок `&#…;`, описание — латиницей.

Кириллицу в описании не используем: страница «Сведения» отдаётся без UTF-8,
и русский текст в ней всё равно выглядит мусором.

## Подпись аддона (необязательно)

Подпись нужна, только если в WebCTRL включён запрет неподписанных аддонов
(обычно на серверах, доступных из интернета). Для внутренних серверов достаточно
неподписанного архива — так работают weather и termoheatmap.

Если подпись всё же нужна, архив подписывается сертификатом, установленным на
сервере:

```powershell
.\build.ps1 -Sign -Keystore "D:\certs\addoncert.keystore"
# пароль — из -Storepass или переменной ADDON_KEYSTORE_PASS
```

В архиве появляются `META-INF/ADDON.SF` и `META-INF/ADDON.RSA`, файл
`META-INF/MANIFEST.MF` получает дайджесты. Проверить подпись:

```powershell
jarsigner -verify dist\twpi.addon
```

Сертификат (`addoncert.cer`) должен быть добавлен на сервере в папку аддонов —
это делается один раз при настройке подписи.

## Сборка

Нужен JDK, Tomcat с `lib\servlet-api.jar` и два jar рядом с проектом:
`directaccess-api-addon-1.7.0.jar` и `json-20251224.jar`.

```powershell
.\build.ps1 -Tomcat "D:\WebCTRL\tomcat" -Jdk "C:\Program Files\Java\jdk-11"
```

Байткод по умолчанию — **Java 8**: работает и на WebCTRL 6.5 (Java 8), и на 9+/11+.
Для современных серверов можно `-Release 11`.

NetBeans/Ant не обязательны: в проекте есть `build.xml` с теми же целями
(`-pre-dist` собирает `webapp/`, `-post-dist` кладёт `dist/twpi.addon`).

### Структура архива

```
info.xml                       ← имя, версия, вендор (читает установщик)
META-INF/context.xml
META-INF/MANIFEST.MF
webapp/                        ← именно запись-каталог, не только файлы!
webapp/index.html
webapp/room.jsp, rooms.jsp, tree.jsp, status.jsp
webapp/WEB-INF/web.xml
webapp/WEB-INF/classes/…
webapp/WEB-INF/lib/json-….jar
```

Важно: в zip должна быть **запись-каталог `webapp/`** (с завершающим слэшем).
WebCTRL при старте проверяет `zip.getEntry("webapp/")` и без неё не считает файл
веб-аддоном: вручную такой аддон ставится и работает, но после перезапуска
пропадает из списка, хотя файл лежит в папке `addons`. `build.ps1` добавляет
directory-записи для всех каталогов; если собираете другим инструментом —
проверьте, что `webapp/` в архиве есть.

`directaccess-api-addon-1.7.0.jar` в архив не кладётся — API даёт сам WebCTRL.

## Настройки помещений

`rooms.jsp` (кнопка «Настроить»). Адреса удобно брать на `tree.jsp`, там же кнопки
для подстановки в поля.

Быстрое заполнение: вставьте адреса по одному в строке — записи с общим родителем
(`…/zone5/zone_temp` и `…/zone5/zone_humidity`) соберутся в одно помещение.

Хранится в файле рядом с WebCTRL, а не внутри аддона (каталог веб-приложения
пересоздаётся при переустановке):

```
<catalina.base>/conf/twpi-rooms.json
```

Если `conf` недоступен для записи — берётся `<catalina.base>` или временный каталог
контекста; фактический путь виден внизу страницы настроек. **Файл стоит бэкапить.**

## Кэш

Дорогое место — чтение трендов: API 6.5 отдаёт на каждый запрос весь архив
(~100 тыс. сэмплов). `SeriesCache` держит часовые ряды по адресу:

- ряд читается на 400 суток и живёт 10 минут;
- список, карточка и месячная история используют одни и те же ряды;
- период и интервалы диаграммы считаются в памяти;
- ошибки не кэшируются, в памяти не больше 64 адресов.

Первый заход после рестарта или после 10 минут — медленный, остальные быстрые.
На главной есть строка «данные из кэша, N мин назад» и ссылка для принудительного
обновления (`api/all?…&fresh=1`).

## Встраивание в интерфейс WebCTRL

Когда аддон открывают не по прямому адресу, а «средством отображения аддонов»,
WebCTRL запрашивает `/{аддон}/include_content` и вставляет ответ в свою страницу
(см. `updatehtml.js`, `AddonSupport`). У аддона должен быть такой эндпоинт, иначе
появляется `The requested resource [/twpi/include_content] is not available`.

У нас это `IncludeContentServlet`: он отдаёт iframe с обычной страницей аддона.
Так тёмный CSS и идентификаторы элементов не пересекаются с интерфейсом WebCTRL,
а переходы (карточка помещения, настройки) остаются внутри iframe. Страница
`index.html?embed=1` в этом режиме прячет собственную шапку и подвал.

`/include_script` тоже объявлен — WebCTRL может запрашивать скрипт аддона отдельно;
отдаём пустой, потому что весь JS лежит на странице.

## API

```
GET  /twpi/api/calc?t=<адрес T>&rh=<адрес RH>&days=30   — разовый расчёт
GET  /twpi/api/all?days=30                              — все помещения
GET  /twpi/api/room?i=0&days=30                         — помещение + интервалы
GET  /twpi/api/rooms                                    — настройки + путь к файлу
POST /twpi/api/rooms                                    — сохранить настройки (JSON)
```

## Диагностика

Если что-то отвечает 404/500 — откройте `/twpi/status.jsp`: версия аддона, Java,
Tomcat, читается ли `web.xml`, зарегистрирован ли сервлет, видны ли DirectAccess
и `org.json`.

Проверено на WebCTRL 6.5 (Java 1.8.0_51, Tomcat 7.0.61, API аддонов 1.4.2).

## Проверка формул

```powershell
tools\selftest.cmd
```

Контрольные точки PI, гармоническое усреднение, окно периода, распознавание
влажности в долях и разбивка диаграммы (день/неделя/месяц).
